# @kapdh/worker

Runtime worker KAPDH (PRD 5.1, 5.5, N-14; ARCHITECTURE §4.8). Prosesor job hidup di modul API
(`modules/<m>/<m>-jobs.module.ts`) dan dimuat lewat `@kapdh/api/worker`; paket ini hanya menjalankannya.

| Komponen          | Perilaku                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dispatcher outbox | Poll setiap `OUTBOX_POLL_INTERVAL_MS` (2 s). Klaim `FOR UPDATE SKIP LOCKED` + lease `locked_until` sebanyak slot antrean kosong, enqueue dengan jobId = dedup key + token lease. Saat mulai diproses, lease diambil alih secara atomik (klaim usang atau klaim yang sama diproses dua kali → `lost`, handler tidak berjalan ganda). Handler topik → `dispatched`, atau `failed` + backoff eksponensial + `last_error` aman, atau `dead` setelah 10 percobaan. Lease diperpanjang selama handler berjalan; proses mati → lease habis → diklaim ulang. |
| Antrean           | BullMQ + ioredis bila `REDIS_URL` diisi (wajib di production; prefix `kapdh:<NODE_ENV>:bull`), inline dalam proses bila tidak. Dua koneksi: konsumen (`kapdh-worker-bullmq`, `maxRetriesPerRequest: null`) dan produsen gagal-cepat (`kapdh-worker-bullmq-producer`, tanpa offline queue, batas waktu 5 s per operasi). Start menunggu Redis siap maksimal 30 s lalu gagal (proses keluar non-zero, dijalankan ulang orkestrator). Data job hanya rujukan (id + lease / nama job + slot + job_id).                                                   |
| Konkurensi        | `WORKER_CONCURRENCY` = total job paralel per proses: separuh (min. 1) untuk job terjadwal, sisanya (min. 1) untuk outbox, sehingga pool kerja `WORKER_CONCURRENCY + 1` selalu menyisakan koneksi untuk heartbeat lease dan finalisasi. Gunakan nilai ≥ 2 di production.                                                                                                                                                                                                                                                                              |
| Penjadwal         | Semua job `registerScheduled` dijadwalkan per slot `floor(now / everyMs)`. Hanya pemegang kunci advisory sesi PostgreSQL (`ADVISORY_LOCK_KEYS.workerSchedulerLeader`, koneksi khusus `kapdh-worker-leader`) yang menjadwalkan; instance lain standby dan mengambil alih bila leader berhenti/mati.                                                                                                                                                                                                                                                   |
| Health            | `GET /healthz` di `WORKER_HEALTH_HOST:WORKER_HEALTH_PORT` (0.0.0.0:3001). 200 `ok`/`degraded` (backlog outbox > 5 menit, event `dead`), 503 `error` (DB/Redis tidak terjangkau, klien BullMQ rusak atau loop konsumen berhenti, loop dispatcher/penjadwal macet `*_stalled` atau gagal terus ≥ 2 menit `*_failing`) atau `stopping`. Berisi umur outbox pending tertua, keterlambatan jatuh tempo, tick penjadwal terakhir. Jangan dirutekan publik. Uptime Kuma: alert pada `status != ok`.                                                         |
| Shutdown          | SIGTERM/SIGINT: berhenti poll dan tick, tunggu job berjalan sampai `WORKER_SHUTDOWN_TIMEOUT_MS` (25 s), lepas kunci leader, tutup koneksi dan pool. Sinyal kedua = keluar paksa. `stop_grace_period` container > timeout + 10 s.                                                                                                                                                                                                                                                                                                                     |
| Log               | JSON pino `service: kapdh-worker`, redaksi kunci rahasia, galat hanya bentuk aman. `job_id` sama di log antrean, log JobRunner, dan audit job (`outbox:<id event>` atau `<nama job>:<uuid>`); id job antrean di `queue_job_id`; `request_id` asal event.                                                                                                                                                                                                                                                                                             |

Env (validasi `loadWorkerEnv`, `packages/config`): basis API minus secret JWT/OTP/TOTP/QR, plus `WORKER_CONCURRENCY`,
`WORKER_HEALTH_PORT`, `WORKER_HEALTH_HOST`, `OUTBOX_POLL_INTERVAL_MS`, `WORKER_SHUTDOWN_TIMEOUT_MS`. `DATABASE_URL` memakai
role `kapdh_worker` (`infra/db/roles.sql`). Koneksi per instance: pool kerja (`WORKER_CONCURRENCY + 1`), 1 koneksi kunci
leader, 1 koneksi health; Redis: klien core + 2 koneksi BullMQ + 1 koneksi blocking per antrean.

Perintah (dari `kapdh-platform/`): `pnpm --filter @kapdh/worker build`, `... start`, `... test` (PGlite; ketahanan Redis
dengan ioredis + BullMQ sungguhan terhadap server RESP tiruan), `... test:pg` (PostgreSQL 17 embedded: leader dua worker,
SKIP LOCKED dan balapan lease lintas koneksi, runtime lengkap sebagai `kapdh_worker` termasuk jalur BullMQ). Image:
`docker build -f infra/Dockerfile.worker .`.
